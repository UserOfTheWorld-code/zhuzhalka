# Подпись Жужалки с версии 0.2

APK для пользователей собираются в варианте `release` и подписываются одним постоянным приватным ключом. Публичный SHA-256 сертификата записан в [`scripts/release-signing-cert.sha256`](../scripts/release-signing-cert.sha256). Gradle проверяет этот отпечаток до сборки release, а упаковщик повторно проверяет подпись и манифест каждого APK. Приватный ключ и пароль никогда не входят в репозиторий, исходный ZIP или артефакты CI.

Версия 0.2.0-beta.1 использует `versionCode = 5000200` для всех ABI и обеих дистрибуций. Каждый следующий опубликованный APK должен иметь больший код. Не возвращайте ABI-зависимые коды: universal и arm64 должны обновлять друг друга. У F-Droid отдельный package ID с суффиксом `.fdroid`.

## Однократный переход с 0.1

Публичная 0.1 была подписана временным debug-ключом GitHub Actions, который не сохранился. Новый сертификат не может заменить его при обновлении. Экспортируйте профили и ссылки подписок, удалите 0.1, установите 0.2 и импортируйте данные. После этого версии с постоянной подписью устанавливаются поверх приложения. Не удаляйте 0.1 до сохранения нужных настроек.

## Локальная сборка в Windows

Ключ `release.jks`, зашифрованный Windows DPAPI пароль `password.dpapi` и публичный сертификат `release-certificate.der` хранятся вне репозитория в `%LOCALAPPDATA%\Zhuzhalka\signing`. Доступ к папке ограничен текущей учётной записью Windows. DPAPI-файл расшифровывается этой же учётной записью; его копия сама по себе не является переносимой резервной копией пароля.

После установки JDK 21, Android SDK и подготовки нативных библиотек:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-signed-release.ps1
```

Скрипт читает защищённый пароль только в процессе сборки, передаёт его Gradle через окружение, не печатает его и запускает Gradle без постоянного daemon. Он не создаёт новый ключ автоматически. APK находятся в `V2rayNG/app/build/outputs/apk/playstore/release/` и `fdroid/release/`.

Проверка конфигурации без полной сборки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-signed-release.ps1 -Tasks :app:verifyReleaseSigning
```

Сохраните приватный ключ и пароль в защищённой независимой резервной копии. Потеря этого ключа лишает возможности выпускать совместимые обновления. Не отправляйте их в чат, публичные файлы или Git. При переносе на другой компьютер восстановите прежний ключ и заново защитите его пароль DPAPI под нужной учётной записью.

## GitHub Actions

Обычные push/PR собирают только debug APK без доступа к секретам. Публикация запускается вручную на `master`, вход `publish_release=true`, тег `v0.2.0-beta.1`; соответствующий релиз должен предварительно существовать как draft. Без настроенного постоянного ключа публикация завершится ошибкой, без подмены подписи на debug.

Только после разрешения владельца передать ключ в GitHub для репозитория `UserOfTheWorld-code/zhuzhalka` создаются два Actions Secrets:

- `ZHUZHALKA_KEYSTORE_BASE64`: Base64 от существующего `release.jks`.
- `ZHUZHALKA_KEYSTORE_PASSWORD`: его пароль; тот же пароль используется для alias `zhuzhalka-release`.

Base64 — кодировка, а не шифрование; её значение также является секретом. В workflow эти данные доступны только шагу подписанной сборки при ручном запуске доверенного `master`. Keystore временно записывается в `RUNNER_TEMP` с закрытыми правами и удаляется после шага. На GitHub нельзя создавать новый ключ для каждого запуска или подменять публичный отпечаток ради прохождения проверки.

Для Linux с уже подготовленными переменными `ZHUZHALKA_KEYSTORE_PATH` (абсолютный путь) и `ZHUZHALKA_KEYSTORE_PASSWORD`:

```bash
ANDROID_BUILD_TYPE=release bash scripts/build-android.sh
python3 scripts/package-release.py --output release-dist
```

Упаковщик принимает только release APK с правильным package ID, версией, кодом, постоянным сертификатом и выключенным `debuggable`. Облачная сборка не равнозначна отдельному тесту её APK в эмуляторе.
